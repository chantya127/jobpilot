# workday notes

### Workday (*.myworkdayjobs.com)
- `wdstart` (cookie decline → Autofill with Resume → Sign In, else Create Account). Each tenant needs its own account. If sign-in fails right after creating the account, the tenant wants email verification: `otp --match myworkday --link`, open the link, sign in again; if none arrives → pending-user.
- `wdresume` (upload + Next). Step 2: `wdinfo; wdsrc` (names, address, phone, <state> — options use diacritics "<State with diacritics>", title Mr, previous-worker No, source, phone type). Step 3: `wdexp` (companies, locations, <current employer> start 08/2025, strips "Company City" first line of descriptions, degree, LinkedIn, resume) — then check Field of Study (`wdprompt fieldOfStudy "Computer Science" "Computer Science"`).
- `wddump` shows every field; `wderr` shows errors; `wdstep` shows the step.
- Dropdowns: `wdpick <formField-id-suffix> "<exact option text>"` (focus + Enter; plain click often doesn't open). On NOTFOUND it prints the options — retry with the exact text.
- Multiselect prompts: `wdprompt <field> <search> <option>`. Textareas: `wdtext <field> "<text>"` (real keystrokes; JS `.value` doesn't persist). If Source is a plain single-select (FactSet, Amgen), use `wdpick source LinkedIn` or click it, never `wdprompt`, which types junk into City or Phone. Call `wdpick` one field at a time, because a `set --` loop fails.
- Terms: `wdterms`. Read the Review page, then `wdclick pageFooterNextButton` (Submit shares that id). Success URL `jobTasks/completed/application`.
- Stuck Next: hidden errors, wait 10–15 s, mouse-click button centre, or `$AB reload`.
