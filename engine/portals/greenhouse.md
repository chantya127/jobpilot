# greenhouse notes

### Greenhouse (job-boards.greenhouse.io, boards.greenhouse.io, grnh.se)
- `?gh_jid=X` on a company site → use `https://boards.greenhouse.io/embed/job_app?for=<company>&token=<X>`. grnh.se links redirect; check the jid isn't already applied.
- Omio (job-boards.eu.greenhouse.io): no email code. ghbase leaves Country empty: `ghcombo '#country' India 'India'` works. Location empty: click #candidate-location, type "<City>, <first letter of state>", Enter. Phone gets a leading 0 and needs a refill. The GDPR processing consent box starts unticked: click it via a snapshot ref (2026-11-15).
- Stripe (stripe.com/careers ?gh_src): embed job-boards.greenhouse.io/embed/job_app?for=stripe&token=<jid>. ghbase leaves Country and Location empty. Education is required: School "<your university>", Degree "Bachelor's Degree". A required "countries you'd work in" checkbox group: tick India via a snapshot ref (a CSS-selector click ticked Australia). An 8-char email code at submit, typed per digit (2026-11-15).
- `ghbase` = resume upload + name/email/country(India)/phone/location(<city>). `ghq` lists question ids/labels/values. After ghbase, ALWAYS check #phone: it often gets a leading 0 ("0<phone> (with a space)") → refill <phone>.
- Text: `$AB fill "#question_<id>" "..."`. React-select: `ghc '#question_<id>' '<type-ahead or empty>' '<option text regex>'` (retries once). Read selections back with `[class*=singleValue]` (the input value stays empty).
- The phone country list (`.iti`) is always in the DOM — ignore those options.
- `ghsubmit` then the 8-char email code (above). Success: URL `/confirmation` or "Thank you for applying" email.

### Greenhouse helper (ghc)
- Option regex matches after `option "`: use `No"` (not `^No`) for an exact Yes/No pick.

## Embedded on the company site (flix.careers/job)
- The Greenhouse form is built into the page itself, with fields named question_<id>. The usercentrics cookie banner covers Submit, so click Deny first. Tick #privacy_policy with JS.

- job-boards.eu.greenhouse.io (e.g. Veeam): "Preferred First Name" is required. The 8-digit security code needs each digit typed into its own #security-input-N after focusing it via JS; typing into the first box keeps only one character. On any board: scrollIntoView + focus #security-input-0 first, or the code goes into #phone; re-check #phone after.
- DigitalOcean (digitalocean.com/careers ?gh_jid=): Greenhouse iframe; open job-boards.greenhouse.io/embed/job_app?for=digitalocean98&token=<jid> (boards.greenhouse.io/embed?for=digitalocean is dead). ghbase country can silently fail: re-run ghcombo "#country" India "India" and verify.
- EU/UK boards (e.g. Deliveroo): answering ANY optional demographic dropdown (even "No") makes the GDPR demographic-consent checkbox mandatory before Submit, and ticking it was blocked by the permission classifier -> leave optional demographic dropdowns unanswered. "Country" combobox there = phone country (type India, pick "India +91"); ghbase leaves it empty.
- Okta (grnh.se → okta.com/company/careers/...): embedded Greenhouse form without #first_name/#resume ids (ghbase fails) plus a visible reCAPTCHA checkbox → pending-user.
- Databricks (databricks.com ...?gh_jid=): embeds job-boards.greenhouse.io/embed/job_app?for=databricks&token=<jid>. "Preferred First Name" is required. ghbase's resume upload may show an uploadFile error; re-run `up "#resume"`. May send an 8-char email code at submit (`otp --match Databricks --len 8`). "Legally authorized" combo: ghc fails → `$AB click "#question_<id>"` then the [role=option] "Yes". JS-ticking sanctions checkboxes can hit the wrong one ("Cuba citizen"): verify before Submit. (2026-11) PDF upload can throw "uploadFile" and block Submit → click "Enter manually" for Resume/CV, paste resume text into #resume_text, fill by hand (not ghbase). Sanctions: "None of the above" in group 1 AND "Not applicable" in group 2. Some combos need a second pick (legally authorized, +91). (2026-11-09) Some embeds have no #resume (ghbase already attached the CV); the only file input is #cover_letter, so don't `up "input[type=file]"` (it lands in Cover Letter → "Remove file").
- ghbase often leaves the phone "Country" combobox empty (Cohere Health, G-P; any job-boards.greenhouse.io form), and submit then fails silently with "Select a country". Run `ghcombo "#country" India "India"` (or click it, type India, pick "India +91") before submitting. Also check #phone for a leading 0 after autofill.
- Fivetran (?gh_jid → job-boards.greenhouse.io/embed/job_app?for=fivetran&token=<jid>): a required privacy-notice combo must be "Acknowledge/Confirm"; ghc with plain "Acknowledge" works (a regex did not). scrollIntoView security-input-0 before clicking it.
- MongoDB (boards.greenhouse.io/mongodb/jobs/<id> redirects to mongodb.com/careers): use job-boards.greenhouse.io/embed/job_app?for=mongodb&token=<id>. Required "Gender Identity" combo + demographic consent checkbox before Submit. Per-digit #security-input-N typing (see the EU note) applies here too. "How did you learn": ghc "LinkedIn" picked "Mogul" → eval-click the option. Gender combo opens only via snapshot-ref click.
- ghc pitfalls (YipitData): regex/lowercase matches can silently not stick → open the combo and click the matching [role=option] via eval. Gender: plain "Male" (a regex like Male" can hit "Third gender"). Phone country can land on "+246 British Indian Ocean Territory" → verify +91 before Submit.

- Coinbase (for=coinbase): Employment + Education sections required (ghbase leaves empty: company-name-0, title-0, start month/year, school, degree, discipline). "AI tools" combo: click, then option click. Phone autofills a leading 0 → refill <phone>. 8-char code: `otp --match Coinbase`. A stale "uploadFile"/"Resume required" error can show with the file attached; Submit still works. Combos: plain click, then eval-click [role=option] (typing closes them); School: type "Pun" → "<your university>".
- Payoneer (payoneer.com/careers ?gh_jid=): open job-boards.greenhouse.io/embed/job_app?for=payoneer&token=<jid>. Privacy combo: focus via JS + ArrowDown, then eval-click the "Yes" option. Email code at submit.
